# 分步更新现有 Docker Compose 部署

这些脚本从当前仓库构建镜像，适用于容器名、Compose 服务名均为 `asspp` 的单文件部署。构建和切换分开执行，并保留原镜像和 Compose 备份。

先在保存账号的浏览器中进入「设置 → 数据 → 导出账号」，保存加密文件及导出密码。账号令牌和 Cookies 存在浏览器 IndexedDB，服务器镜像备份不包含它们。导出只读取本地账号，不会重新认证。苹果已作废的令牌不能靠导入备份或回滚镜像保证恢复。

## 构建

服务器需要 Docker Compose v2、Python 3、sha256sum，以及拉取基础镜像、npm 依赖和苹果公共资源的网络访问。建议在空闲时构建，避免资源竞争。

在当前仓库根目录执行：

```sh
sudo bash tools/compose-update/build.sh
```

脚本从现有容器标签找到原部署目录。它对比修改前后的完整 Compose 配置，确认只有镜像引用发生变化，然后保存原配置、为旧镜像添加备份标签，并构建当前源码。测试或构建失败时，现有容器和原 Compose 保持原样。

构建成功后也不会立即切换。终端会输出带完整路径的 `sudo bash .../activate.sh` 命令。账号已备份、现有下载结束后，再执行该命令。切换会短暂断开连接。

## 切换和回滚

切换脚本检查 Compose、当前镜像和待切换镜像是否仍与构建时一致，只重建 `asspp` 服务。启动检查失败会自动恢复旧配置和镜像。成功后下载并校验 SAP 公共资源、检查苹果证书接口；若资源准备失败，新镜像仍保留，脚本返回退出码 2，需按错误输出处理或执行回滚。

使用终端输出的 `rollback.sh` 完整路径可以手动恢复本次更新前的镜像和 Compose。配置备份可能含环境变量，保存在原部署目录下权限为 700 的 `.asspp-sap-backup.*` 目录。

保留当前仓库目录直到切换和资源检查结束。更新后继续使用原浏览器和原网址，已有可用账号无需重新认证、删除重加或清除网站数据。新增登录先用备用账号验证；「获取许可」原有流程会尝试重新认证账号。

## 脚本检查

```sh
python3 tools/compose-update/tests/test_update.py
```

此检查使用模拟 Docker，覆盖分步构建与切换、手动回滚、构建失败、启动失败、构建期间修改配置和切换前修改配置。不代替真实服务器构建、网络及账号登录验证。
